# 页面说明

> 原型文件：`prototype/svg/*.svg`（可编辑矢量图，用于导入原型工具）
> 效果图：`prototype/png/*.png`
> 可点击演示：用浏览器打开 `prototype/index.html`

## 全局设计规范

| 项目 | 规范 |
| --- | --- |
| 画布尺寸 | 375 × 812（微信小程序标准尺寸） |
| 主色 | 微信绿 `#07C160`（主按钮、选中态、招领标签） |
| 辅助色 | 橙色 `#FF8F1F`（寻物标签） |
| 正文色阶 | 主文字 `#1A1A1A` / 次要 `#666` / 辅助 `#999` |
| 圆角 | 卡片 12px，按钮 24px（全圆角），输入框 8px |
| 字体 | PingFang SC / Microsoft YaHei |
| 底部导航 | 首页 · 发布 · 我的（三个 Tab，发布按钮常亮绿色） |

**为什么用绿色和橙色区分？**
"招领"（有人捡到了，东西在等你）用绿色，传递"可以放心、有希望"的信号；"寻物"（东西丢了，在着急）用橙色，传递"需要注意、有待解决"的信号。两种状态在列表、详情、我的发布三个页面中颜色完全一致，用户扫一眼就能分辨，不需要读文字。

## 01 首页

**作用**：软件的唯一入口，让用户一进来就能看到最新的失物和招领信息。

| 区域 | 元素 | 交互 |
| --- | --- | --- |
| 顶部 | 页面标题「校园失物招领」+ 小程序胶囊按钮 | — |
| 搜索区 | 搜索框，占位文字「搜索物品名称，如 校园卡、钥匙」 | 点击 → 04 搜索页 |
| 筛选区 | 胶囊按钮：全部 / 寻物 / 招领；右侧「最新发布 ▾」 | 点击切换筛选 |
| 列表区 | 信息卡片 × N，每张包含缩略图、类型标签、标题、地点时间、发布者 | 点击卡片 → 06 信息详情 |
| 底部导航 | 首页 / 发布 / 我的 | 点击跳转 |

**卡片信息层级设计**：一张卡片上必须回答"**这是什么 → 在哪丢的 → 什么时候 → 谁发的**"四个问题。因此标题字号最大（15px 加粗），地点时间其次（12px），发布者再次（12px 浅灰）。用户不需要点进去就能判断这条信息跟自己有没有关系。

## 02 发布信息

**作用**：寻物和招领共用同一张表单，通过顶部的分段控件区分类型。

| 顺序 | 字段 | 类型 | 必填 |
| --- | --- | --- | --- |
| 1 | 类型 | 分段控件（寻物 / 招领） | ✅ |
| 2 | 物品照片 | 图片上传（虚线框） | ⭕ |
| 3 | 物品名称 | 单行输入 | ✅ |
| 4 | 物品分类 | 标签选择（可横向滚动） | ✅ |
| 5 | 地点与时间 | 双列输入 | ✅ |
| 6 | 详细描述 | 多行文本，限 100 字 | ⭕ |
| 7 | 联系方式 | 单行输入，提示"仅详情页可见" | ✅ |

**设计考虑**：

- **为什么类型放在最上面？** 用户点进发布页时，脑子里第一件事是"我要发寻物还是招领"，而不是"物品叫什么"。先定类型再填内容，符合思维顺序，也能让下方的文案（如"拾取地点"与"丢失地点"）随之调整。
- **为什么用标签选择而不是下拉框？** 物品分类只有 6 个选项，全部平铺出来用一次点击就能选完，比"点开下拉框 → 滚动 → 选中"少两步。
- **为什么只有 1 个必填的描述字段？** 表单越长，发布意愿越低。物品照片和详细描述都设为选填，保证最短路径下（只填 5 个必填项）30 秒内可以发完。

## 03 发布成功

**作用**：给出明确的成功反馈，并提供下一步去向，避免用户"发完之后不知道去哪了"。

| 元素 | 说明 |
| --- | --- |
| 绿色对勾 | 视觉上的成功信号 |
| 主文案「发布成功」 | 明确的结果告知 |
| 副文案 | "你的信息已发布成功，可在「我的发布」中查看和管理" |
| 主按钮「查看我的发布」 | → 07 我的发布 |
| 次按钮「返回首页」 | → 01 首页 |

**设计考虑**：弹层遮罩让用户无法忽略这个反馈；主次按钮的视觉权重差异（实心绿 vs 纯文字），引导用户优先去"我的发布"确认结果，同时保留了"返回首页"这个低成本的退路。

---

## 04 搜索页

**作用**：搜索的输入态。除了输入框，还提供搜索历史和热门搜索。

| 区域 | 元素 | 交互 |
| --- | --- | --- |
| 顶部 | 返回按钮 + 搜索框（已填入"校园卡"）+ 取消 | 点击搜索框 → 05 搜索结果 |
| 搜索历史 | 标签：校园卡 / 宿舍钥匙 / 雨伞 / 蓝牙耳机 / 学生证 / 三教 / 一卡通；右上角「清空」 | 点击标签 → 05 搜索结果 |
| 热门搜索 | 排行榜 1–5，前两名带「热」标记 | 点击 → 05 搜索结果 |

**设计考虑**：很多同学打开搜索框时其实**不知道该搜什么词**——丢了东西的人可能只记得"一张卡"，而不是"校园卡"。把校园里最高频的物品名直接列出来，用户点一下就能搜，把"输入"这个动作降级为"选择"。

---

## 05 搜索结果

**作用**：展示搜索结果，帮助用户快速判断哪一条与自己有关。

| 区域 | 元素 | 说明 |
| --- | --- | --- |
| 结果统计 | "找到 12 条相关信息" | 先告诉用户有没有结果 |
| 分类筛选 | 全部 / 寻物 / 招领 + 地点筛选 | 在结果中继续缩小范围 |
| 结果列表 | 卡片，**标题中的关键词用绿色高亮** | 让用户一眼看到"哪一条提到了校园卡" |

**设计考虑**：搜索结果页复用了首页的卡片样式，保持一致性，降低学习成本。关键词高亮是这一页的核心：用户扫视列表时，绿色高亮的"校园卡"三个字就是视觉锚点。

---

## 06 信息详情

**作用**：完整展示一条信息，并引导用户联系发布者。

| 区域 | 元素 |
| --- | --- |
| 顶部 | 物品大图（占位图，实际为物品照片） |
| 标签行 | 「招领」（绿）/「寻物」（橙）+ 物品分类 |
| 标题 | 物品名称 |
| 信息行 | 地点 / 时间 / 发布人 |
| 描述区 | 物品详细描述 |
| 安全提示 | "请勿提前透露物品全部特征，以便核实失主身份" |
| 发布者 | 头像、昵称、学院、发布时间、"TA 的其他发布 ›" |
| 底部操作栏 | 收藏 · 分享 · **联系 TA**（主按钮） |

**设计考虑**：

- **底部操作栏常驻**：详情页内容可能很长，把"联系 TA"固定在底部，用户任何时候想联系都能一次点到。
- **安全提示**：这是失物招领类产品特有的一环。如果失主只说"这是我的"，拾得者无法判断真假。提示失主不要写全特征（比如"卡号后四位是多少"），能让归还过程多一道简单的验证。
- **不做站内聊天**：点击"联系 TA"后弹出发布者的微信号，长按复制，再到微信里添加好友。这复用用户已有的社交工具，也让双方后续的沟通更自然。

---

## 07 我的发布

**作用**：管理自己发布的信息，是本设计中"**修改信息状态**"功能的落点。

| 区域 | 元素 |
| --- | --- |
| 用户信息 | 头像、昵称、学号与学院 |
| 数据统计 | 我发布的 3 / 已解决 1 / 我的收藏 2 |
| 状态筛选 | 全部 / 寻物 / 招领 / 已解决 |
| 信息列表 | 卡片 + 操作：**标记为已解决** · 编辑 · 删除 |
| 已解决的信息 | 右上角显示灰色「已解决」标签，不再提供"标记"操作 |

**设计考虑**：物品归还之后如果信息继续挂在首页，既浪费其他同学的时间，也降低了平台的可信度。因此给发布者一个"标记为已解决"的出口，标记后信息自动从首页和搜索结果中下架，只在"我的发布"里留档。
